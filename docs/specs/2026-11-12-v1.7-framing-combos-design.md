# TV Photos 1.7: framing, hiding, combinations, remote ◀ ▶

Approved in chat on 2026-11-12. Builds on 1.6 (versionCode 7).

## Goals

1. **Framing.** Tapping a photo on the phone page opens an editor that shows the TV's 16:9 frame over the
   photo, with the cut-off parts dimmed outside it. Drag moves, pinch or a slider zooms, from "whole photo"
   (black bars) up to 4x. Save stores it; Reset removes it. Unframed photos keep following the global
   *Fill the screen* setting.
2. **Hide.** Every photo and every combination has a *Show on TV* switch. Hidden items stay stored and
   listed (dimmed, tagged *Hidden*); the screensaver skips them. Select mode can hide or show several.
3. **Combine.** Select 2-4 photos, tap Combine, pick a layout for that count:
   - 2: `pair` (two halves)
   - 3: `row3` (three columns) or `big3` (left box 2/3 wide, two stacked boxes on the right)
   - 4: `grid4` (2 x 2)

   A combination is a slide of its own, with its own framing per box and its own Show switch. A photo
   can be in several combinations and still shows alone unless hidden. Selection order is the starting
   box order; *Swap* rotates photos between boxes. Boxes are separated by a thin black gap. Deleting a
   combination keeps its photos; deleting a photo warns, then removes the combinations that use it.
4. **Remote.** In the screensaver, DPAD ◀ goes back through the slides already shown, ▶ goes forward
   through them and then to a new random slide; both restart the timer. Any other key closes the
   screensaver, as before.

## Framing model (shared by phone and TV)

A framing is `{x, y, z}`: `x, y` are the point of the photo (0..1 of its width and height) drawn at the
centre of the box, `z` is the zoom relative to "cover". For a box `w x h` and a photo `pw x ph`:

```
cover = max(w/pw, h/ph);  fit = min(w/pw, h/ph)
z     = clamp(z, fit/cover, 4)
s     = cover * z;  dw = pw*s;  dh = ph*s
left  = dw >= w ? clamp(w/2 - x*dw, w - dw, 0) : (w - dw)/2
top   = dh >= h ? clamp(h/2 - y*dh, h - dh, 0) : (h - dh)/2
```

No framing = `{0.5, 0.5, 1}` (cover), except a single photo with *Fill the screen* off, which uses
`z = fit/cover` unless the photo is within 20 % of the screen's shape (the 1.6 rule).

Layout boxes are fractions of the screen, with a gap of 8 px at 1920 wide (scaled):

| Layout | Boxes (x, y, w, h as fractions before the gap) |
|---|---|
| `pair` | (0,0,½,1) (½,0,½,1) |
| `row3` | (0,0,⅓,1) (⅓,0,⅓,1) (⅔,0,⅓,1) |
| `big3` | (0,0,⅔,1) (⅔,0,⅓,½) (⅔,½,⅓,½) |
| `grid4` | (0,0,½,½) (½,0,½,½) (0,½,½,½) (½,½,½,½) |

## Storage

`files/library.json`, written atomically (temp file + rename) under a lock:

```json
{"photos": {"<name>.jpg": {"x":0.5, "y":0.4, "z":1.2, "off":true}},
 "combos": [{"id":"c<13 digits>_<6 hex>", "layout":"pair", "off":false,
             "cells":[{"p":"<name>.jpg","x":0.5,"y":0.5,"z":1}]}]}
```

Photo entries exist only when a photo has a framing or is hidden. Unknown photo names in combos are
dropped on load. Photo files, the PIN and settings are unchanged.

## Server API (all behind the existing cookie)

| Route | Body | Effect |
|---|---|---|
| `GET /api/photos` | | adds `meta` (the photos map), `combos`, keeps the 1.6 fields |
| `POST /api/frame` | `name, x, y, z` or `name, reset=1` | stores or removes a photo's framing |
| `POST /api/show` | `on=0/1`, `names=a,b`, `combos=c1,c2` | hides or shows |
| `POST /api/combo` | `id?` + `layout` + `cells` (JSON) + `off?` | creates or replaces; returns `id` |
| `POST /api/combo/delete` | `id` | deletes a combination only |
| `POST /api/delete` | `names` | 1.6 behaviour, and drops combos that use them |

Validation: names match the stored-photo pattern and exist; layout is one of the four; cell count
matches the layout; numbers are finite and clamped (`x, y` 0..1, `z` 0.05..4).

## TV side

- `Library` (new): loads, edits and saves `library.json`; the framing maths and the layout boxes live in
  `Framing` (new, pure Java) so they can be unit tested on the JVM.
- `PhotoDream`: builds the slide list each round from `Store.list()` + `Library` (visible photos +
  visible combos), shuffles it, and draws each slide with a `SlideView` (new) that paints each box's
  bitmap with the framing, clipped to its box. Crossfade as in 1.6. Interactive dream:
  `dispatchKeyEvent` handles DPAD_LEFT/RIGHT on key down (repeats ignored) and calls `wakeUp()` for any
  other key down. Keeps a history of the last 50 slides for ◀.
- Decoding: per box, sampled so the bitmap stays at least the box size times the zoom.

## Phone page

- Header count: `N photos · M combinations · K hidden`.
- Sections: *Combinations* (only when there are some), then *Photos*. Combination tiles show the layout
  with the boxes' thumbnails. Hidden tiles are dimmed with a *Hidden* tag.
- Select mode bar: Combine (2-4 photos), Hide, Show, Delete.
- Editor (photos and combinations): a stage with the 16:9 frame; the photo overflows the frame and the
  overflow is dimmed. Pointer events: one finger drags, two fingers pinch. A zoom slider for the
  selected box. Buttons: Save, Reset (photo) or Swap (combination), layout choice for 3 photos, the
  *Show on TV* switch, Delete.
- The same framing function as the TV (a JS copy of `Framing`).

## Testing

- JVM unit tests for `Framing` (cover, fit, clamping, zoom limits, layout boxes).
- Phone page on a localhost mock at 375 x 812 in the built-in browser.
- On the TV, with screenshots: a framed photo, each layout, a hidden item skipped, ◀ ▶ via injected keys
  and then the real remote by the user. Existing photos, the PIN, weather and settings must survive the
  update.
